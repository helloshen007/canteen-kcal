# `deprecated` 标注核对与修正

## 核对依据与范围

本次使用 Hugging Face 数据集 `Sebastianrtj/food-nutrients` 的固定版本
`bb00a088f5b963635da23711766af90e25b9f4a9`：

- 元数据：`metadata.jsonl`，共 3,260 条菜品记录。
- 原始元数据 SHA-256：`77401dbd6f7e75fde017cc3f6efec24cb144e52abbe0cec2b52164451c4dec53`。
- 下载地址：<https://huggingface.co/datasets/Sebastianrtj/food-nutrients/resolve/bb00a088f5b963635da23711766af90e25b9f4a9/metadata.jsonl>。
- 图片：该版本 `test/<dish_id>.png`，本地转为 RGB JPEG。对下表六张图片逐张目视核对，均可见红色西瓜块；其余可见配菜也与元数据对应。
- 原项目划分清单 `data/dish_ids.json` 不变：前 40 张标定、后 20 张测试。六张受影响图全部属于测试集。

官方 Nutrition5k README 说明其原始食材表按 ingredient ID 记录：
<https://github.com/google-research-datasets/Nutrition5k#dataset-structure>。
原始表在 Google Cloud Storage；本次运行环境未能访问该存储域名，因此**不声称已从官方原表核实其原始食材名称**。本次名称修正依据是固定版本的 ID 关联、六张原图的人工核对和对应营养值，记录为本项目审计修正。

## 不能按字符串全局替换

HF 元数据把两种不同食材都命名成了 `deprecated`：

| ingredient ID | 元数据出现次数 | 每 100g 营养（kcal / 蛋白g / 脂肪g / 碳水g） | 处理 |
|---|---:|---|---|
| `ingr_0000000458` | 10 | 30 / 0.6 / 0.1 / 7.6 | 六张选中原图确认西瓜；仅这个 ID 映射为 `watermelon` |
| `ingr_0000000453` | 21 | 52 / 14 / 0.2 / 0.3 | 不在选中的 60 张图内，保留独立的 `unresolved ingr_0000000453`，不推断具体食材 |

旧代码既把字符串 `deprecated` 整体视为不可见，又在营养表中按名称混合聚合这两个不同 ID，得到 48.26 kcal/100g、11.72g 蛋白等不适用于西瓜的密度。现已取消这种排除和混合。

元数据中另有一个空名称 ID `ingr_0000000546`，也按 ID 保留为独立的 `unresolved` 条目。任何 `unresolved` 食材若进入选中评估样本，生成真值会直接报错，要求继续人工核对；不会当作不可见食材而静默归零。

全量元数据还包括 110 次原名为 `watermelon` 的记录。纠正 0458 后，营养表按同一规范化食物名加权聚合 120 条西瓜记录，得到 30 kcal、0.6g 蛋白、0.19g 脂肪、7.6g 碳水/100g。这个 0.19g 脂肪来自全部同名西瓜记录加权，并非直接把单个 0458 的 0.1g 复制到整张营养表。

## 六张样本修复明细

下表“西瓜克数/热量”直接来自各原始 ingredient 条目。可见总量包括图内其他食材，不等于仅西瓜的量。

| 图像 ID（均为 test） | 西瓜克数 | 西瓜 kcal | 旧可见总克数/kcal | 新可见总克数/kcal | 难度变化 |
|---|---:|---:|---|---|---|
| `dish_1558027001` | 68 | 20.4 | 0 / 0 | 68 / 20.4 | none → single |
| `dish_1558027243` | 68 | 20.4 | 95 / 243.0 | 163 / 263.4 | few → few |
| `dish_1558028142` | 73 | 21.9 | 0 / 0 | 73 / 21.9 | none → single |
| `dish_1558028194` | 73 | 21.9 | 99 / 206.1 | 172 / 228.0 | few → few |
| `dish_1558028606` | 65 | 19.5 | 0 / 0 | 65 / 19.5 | none → single |
| `dish_1558028772` | 65 | 19.5 | 127 / 44.5 | 192 / 64.0 | few → few |

保留项目原有“按逐食材 calories 求和、浮点 round 到一位小数”的可见热量口径。`dish_1558028194` 逐项十进制精确和为 228.05；原始 `total_calories` 为 228.050003。两种浮点求和/舍入途径可使 `total_kcal` 为 228.1、`visible_kcal` 为 228.0，差 0.1 kcal；不将这种舍入差异误认为缺失食材。

## 对实验的影响

- 40/20 划分保留，标定集未受这六张图的名称修正影响。
- 测试难度从 12 single / 5 few / 3 none 改为 **15 single / 5 few**。
- 共享词表从 23 类改为 **24 类**，新增 `watermelon`。词表取自修正后的 `visible_dishes`，两种方法必须共用。
- 标定集均值基线仍为 90.6175 kcal；根据修正后的测试真值，基线热量 MAE 从 72.6435 改为 **70.6935 kcal**（报告显示 70.69）。
- 旧的 YOLO 文本类别、旧 VLM 提示词、逐图预测及汇总表不再代表修正后的 24 类实验。需要使旧缓存失效，再重新提取/推理、标定和评估。仅改真值后对旧结果重算只能算“旧模型输出重评分”，不能称为新词表完整重跑。
- 缺失的原始大模型回复不能补造，需实际重跑或提供原实验回复。不能拿旧汇总表当成已复核的逐图证据。

## 对应代码

- `data/labels.py`：ID 级名称修正规则及可见性规则。
- `data/build_gt.py`：可导入的 `build_ground_truth()`，默认从固定清单和元数据生成两个 CSV；选中样本有未知标签时拒绝生成。
- `detector/vocab.py`：从修正后的 `visible_dishes` 生成闭集词表。

运行：`python -m data.build_gt`。元数据缺失时，先按 README 的数据准备步骤下载。
